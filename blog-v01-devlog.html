v0.1 Devlog — First Working Prototype

Shipping the first prototype to GitHub. What I built, what broke, and what I learned.

The Goal for v0.1

From my problem statement post, I locked in one rule for this version: one feature, working end-to-end. No dashboard, no web app, no fancy UI. Just a Python script that takes shot data and outputs a visual shot map.

If I couldn't get that working, nothing else would matter.

What I Built

v0.1 is a command-line Python script. You feed it a CSV with shot data — player name, minute, x/y coordinates on the pitch, and outcome (goal, on target, off target, blocked) — and it outputs a PNG shot map using matplotlib. 

# example input: shots.csv
player,minute,x,y,outcome
Lucas,12,88,34,goal
Marcus,27,75,18,off_target
Javier,44,92,41,on_target
Lucas,67,81,29,blocked

The script reads that CSV with pandas, draws a pitch using matplotlib patches (rectangles, circles, arcs), then plots each shot as a colored marker — green for goals, yellow for on target, red for off target, grey for blocked.

What Actually Broke

A few things I didn't anticipate:

  • Coordinate system confusion. I was plotting x/y from the top-left corner, but soccer pitch coordinates in most data standards put (0,0) at the center. Spent an embarrassing amount of time wondering why all my shots were in the wrong half.
  • Matplotlib's aspect ratio. A pitch is roughly 105m × 68m. If you don't lock the aspect ratio, it renders as a square and everything looks wrong. Needed ax.set_aspect('equal').
  • Overlapping markers. Multiple shots from nearly the same spot stack on top of each other and look like one shot. Didn't fix this in v0.1 — punting it to v0.2 with some jitter or size encoding.

Lesson learned: The bugs that take longest aren't the ones where Python throws an error. They're the ones where it runs fine and draws something that looks slightly wrong. Always test with data you already know the answer to.

The Code Structure

Kept it as simple as possible for v0.1. Three functions:

  • load_data(filepath) — reads and validates the CSV
  • draw_pitch(ax) — draws all pitch markings onto a matplotlib axis
  • plot_shots(ax, df) — plots each shot with the right color and marker

Total: about 90 lines including comments. That felt right for a first version.

Showing It to My Coach

I ran it on data I manually entered from our last three games and showed my coach the output. His first question: "Can you show me where we're losing the ball in the midfield, not just shots?"

That's v0.2.

His second question: "Can I enter data on my phone without a spreadsheet?"

That's probably v0.4 or v0.5.

Both questions were useful. The first told me the right next feature. The second told me where the product eventually needs to go without forcing me to build it before it's needed.

What's in v0.2

Based on that feedback, v0.2 will add ball loss tracking — plotting where possession is lost on the pitch, categorized by type (bad pass, tackle won, out of bounds). Same pipeline, different data type, more tactical value.

I'm also fixing the overlapping marker problem in v0.2 since it came up when showing the map to my coach — he couldn't tell if a cluster was 2 shots or 6.

GitHub: v0.1 is live at github.com/mr-devlinder. README explains how to run it and what format the CSV needs to be in.
