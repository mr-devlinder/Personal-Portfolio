CyberPatriot Season Recap

Our team's approach, what we defended, where we fell short, and what I'd do differently.

What Is CyberPatriot?

CyberPatriot is the national high school cybersecurity competition run by the Air Force Association. Teams are given virtual machines running Windows and Linux that have been deliberately misconfigured with security vulnerabilities. Your job is to find and fix as many as possible within a timed window — while keeping required services running.

It's scored automatically. Every vulnerability you patch scores points. Every required service you accidentally break loses points. The pressure is real.

Our Approach

Going in, we divided responsibilities by OS. I took Linux — specifically Ubuntu — because I'd been working through OverTheWire Bandit and felt more comfortable there than on Windows Server. Two teammates handled Windows 10 and Windows Server. The fourth handled Cisco networking.

Our checklist for each machine hit the same categories in the same order every round:

  • User account audit — remove unauthorized users, disable guest accounts, enforce password policies
  • Services and processes — kill anything that shouldn't be running (Telnet, FTP if not required, etc.)
  • Software — remove prohibited software listed in the scenario README
  • Updates — run system updates where allowed
  • Firewall — enable and configure, allow only required ports
  • File permissions — fix world-writable files, check sudoers
  • Forensics questions — answer the scenario-specific questions for bonus points

What We Got Right

The checklist approach worked. Having a repeatable process meant we didn't miss obvious things under time pressure. In Round 1 we scored consistently on user audits and services — the stuff that's always there regardless of the specific scenario.

Dividing by OS was also the right call. Context switching between Linux and Windows in a 6-hour window is slow. Owning one system deeply is faster than knowing two systems shallowly.

Where We Fell Short

Forensics questions. These are scenario-specific and require actually reading the README carefully. We rushed this in Round 2 and left points on the table that we should have gotten — the answers were there, we just didn't look.

Service breakage. In Round 3, I hardened SSH too aggressively and briefly broke remote access. Caught it before the scoring window closed, but it cost time. The lesson: always verify required services are still functional after making changes.

The thing nobody tells you: CyberPatriot is as much a time management competition as a technical one. Knowing what to fix is table stakes. Knowing what order to fix things in — and when to stop and move to the next machine — is what separates Gold from Platinum.

What I'd Do Differently

  • Practice with real scored images before Round 1. We used practice images but didn't simulate the time pressure well. Next year we're doing full timed mock rounds.
  • Assign a dedicated forensics reader. One person reads the scenario README thoroughly and owns the forensics questions. They don't touch the machines until the questions are answered.
  • Build a personal Linux hardening script. The same fixes show up every year. A script that applies safe, non-service-breaking hardening automatically could save 20–30 minutes per round.

Next Year

Target: Platinum tier. That means tighter execution, better forensics, and not leaving any easy points behind. I'm starting OverTheWire Natas over winter break to sharpen web-specific thinking, and I'll build that Linux hardening script before September.

If you're thinking about competing and you're on the fence — do it. The pressure of a real scored environment teaches you things that no tutorial can.
